## 问题（按严重程度）

### 阻塞

**A. P6.6 探测比较的查询构成不对等，AUC 差可以由构成而不是由环路结构决定。**
- 环路读数的构成：奇 = (1 或 3 次, 0 次)，偶 ≥ 2 = (2, 0)；参照分支一律零进入。
- 基线的构成（`c6lib.py:244`）：奇取自 {(1,0), (0,1), (1,2), (2,1)}，偶取自 {(1,1), (2,0), (0,2), (2,2)}。任何一支都不超过 2 次进入，而且一半的对两支都进过开关。

所以 (i) 的 AUC 差和 (iii) 中探测那一路的数据效率，混进了两种难度差：一是"数到 3"，二是"两支都带误差"。

真值核查：用"数到 2 封顶"的预测器，环路分层 AUC 0.706，基线 0.878，差 −0.17，而胜出幅度只要求 0.05。方向也可以反过来：如果模型的误差随进入次数在两支上累积，基线的 (1,1)、(2,2) 对会被抬高，基线 AUC 下降，和乐就会"胜出"。(iii) 不看 gate，所以在 250 / 500 条数据的模型上，这个混淆最大。

**修正：** 让基线的类别与环路同构。奇取 {(1,0), (0,1), (3,0), (0,3)}，1 次与 3 次各半；偶 ≥ 2 取 {(2,0), (0,2)}；零取 {(0,0)}。终点仍取不是 z 的随机 R0 格，长度照样用撞墙补齐。这样两种读数唯一的差别就是"终点是否回到 z"。现在的类别可以留作副读数。

**B. 缺 run 不会判 INCOMPLETE。**
`aggregate` 只检查 H-act 主 run 齐不齐（`c6_score.py:328–331`）：
- 对照 run 缺失或没计分时，P6.3 直接记为不成立（347–350）；
- 250 / 500 的数据效率 run 缺失时直接跳过（400–401）。

伪造 run 核查：C-vis 全部缺失 → `READOUT_DEAD`，status 为 `dead`；数据效率 run 全部缺失 → `merged_into:HCDP`。

**修正：** 判定所需的 42 个 run（gate.json 与 scores.json）缺任何一个，都输出 `INCOMPLETE`。

**C. 对照模型没学会，会被判成"读数死"，违反清单第 11 条（"死"只在同分布模型检查通过时成立）。**
P6.3 的 (b)(c) 不成立，可能只是因为 C-open / C-vis 模型没学会：gate 不过，或者预测错了。但 FAIL_CHECKED 只看 H-act 的 `model_check`（`c6_score.py:358, 366`）。对照 run 自己的 `model_check` 已经算了（`readouts` 对每个 run 都算），却没有用上。

伪造 run 核查：C-vis 的 gate 不过 → `dead`；C-open 的 `model_check` = 0.3 而且读数有噪声 → `dead`。

**修正：** 某个种子的 P6.3 若因对照 run gate 不过或其 `model_check` < 0.95 而不成立，记为"未检查的失败"。一个尺寸要判 FAIL_CHECKED，它的失败种子必须都通过模型检查（H-act 和相应的对照都要），否则判 FAIL_UNCHECKED，结果为不确定。prereg §6 里"对照 run 的 gate 不过记为不成立"一句相应改为"记为未检查的不成立"。

A、B、C 都要改冻结文件（`c6lib.py`、`c6_score.py`、`prereg.md`），所以要重新冻结并让 Z 点头。改动不大，建议连同测试一起加：缺 run、对照失败、同构基线各一个测试。
