## 5. 剩下的问题

### 阻塞

**R1. "θ gate 不过且 κ̂ > 5 → 不确定"会把第 4 条点名的折叠结局移出分母。**
- 起因：折叠到守恒量上的潜空间，θ 方向的局部长度只剩 sin θ·dθ 这一项，所以 κ̂ 本来就偏大。
- 实测（新的状态种子）：
  - (E, sign ω) 的 κ̂ 为 2.9–5.7，8 个样本里有 2 个 > 5（5.70、5.38）；
  - 它的 8 维光滑嵌入在 2 个样本里读 3.2 和 5.9；
  - (E, 3ω) 读 4.4–4.5，(cos θ, 3ω) 读 4.0–4.1，离阈值都很近。
  - 这些潜空间的 θ gate R² 都在 −0.14 到 −0.06 之间，与 ω 主导造成的假阴性完全不是一回事：拉伸的撕开图 / 粘合图在 κ = 9.5 时读 0.989–0.993，κ = 15 时 0.984–0.988，κ = 30 时 0.965–0.971，κ = 60 时 0.90–0.93。
- 后果：P0.4 的 jepa 臂中，这些折叠 run 不进分母，粘合率被抬高。例如 5 个粘合 + 1 个撕开 + 3 个 κ̂ > 5 的折叠：现在读 5/6 → T；按第 4 条应读 5/9 → F。
- 改法（需要 Z）：θ gate 不过时，只有 κ̂ > 5 且 r2_min ≥ 0.8 才记为不确定；r2_min < 0.8 一律记为不承载 θ。0.8 落在两类之间：拉伸图到 κ = 60 仍 ≥ 0.90，完全折叠 ≤ 0。部分折叠（10–20% 的状态）的 κ̂ ≈ 1，不受这条影响。另加一个单元测试：伪造 θ gate 的 r2_min = −0.1、κ = 5.9，应当得到 not_carrying_theta。

### 非阻塞（建议随同一次修订一起改）

- **N1. 发散的 run 这条路径不通。**
  - `c0_queue.py` 用 `&&` 串起训练和计分，`train` 发散时返回 1，计分不会执行。重启队列时，因为没有 `"final"`，又会重新训练。所以这个 run 一直是"缺失"。
  - 加上 B2：任何一个 angle_cs 的 run（9 个负对照或 cs-recon）缺失，都会让整格变成 INSTRUMENT_INSUFFICIENT。
  - 如果手动跑计分写出桩文件，主世界 angle_cs 或像素 run 的桩会让 `aggregate` 在 P0.7 那一行抛 `KeyError: 'h1'`（实测：桩放在 cs-recon_S_s0 时崩，放在 raw 臂或负对照上不崩）。
  - 改法：队列在发散时照样执行计分，并且不再重训；P0.7 跳过被排除的 run（这一处在冻结文件里）。
- **N2. 快速转动接缝比在结构上恒为 nan。**
  - 原因：|ω| ≥ 半宽 / dt = 1.2 时，切口后 0.12 rad 内的每一点，它的前一帧都在切口另一侧，都是跨切口窗口，被 v2 去掉了。所以 |ω| ≥ 1.6 时没有任何跨切口点对。
  - 推论：主读数 SR_v2 只看 |ω| ≲ 1.2 的穿越（切点对 3905 个，v1 是 10630 个）。这个覆盖范围没有写进 §5 和 `calibration.md`。
  - 按速度部分粘合的图（`emb_arc_omega`，两种方向 × 2 个分析集）：一致性表都判不确定，没有判反，但这一类没有进 §11 的校准。
  - 改法：快速转动副读数改用保留跨切口窗口的 v1 `seam_ratio`（与 pilot 口径相同，只作描述），并在 §5 写明 v2 的速度覆盖。
- **N3.** 设备对照要在队列里走第二种设备，例如加一个开关，只跑 role = device_control 的行。
- **N4.** 像素 STOP 时保留阶段 1 的改动，这改了 v1"P0.1 或 P0.2 失败 → 停，不更新任何邻居"的语义。已经写明，请 Z 明确点头。
