## 3. 问题（按严重程度）

### 阻塞

**B1. "不确定"留在分母里，于是"仪器判不出"变成了"预测失败"。这与 prereg 自己的 §11 相矛盾。**
- 代码：`arm_rates` 的分母是全部未排除的 run（`c0_aggregate.py:58-62`），只看排除数判可评判，然后 `tri` 返回 F。
- 伪造测量的结果：angle_raw 四个臂全部 inconclusive 时，P0.3 = F，P0.4 = (F, F)，状态 DECIDED，并且格 0 status → dead、exists high → mid、格 4 yields 上调。而 §11 写的是"判不出来（I）"。
- 另一例：recon-mse 5 个 torn + 4 个 inconclusive → P0.3 = F → dead。
- 按校准里的判定率（撕开图 60% 判撕开，粘合图 75% 判粘合），即使事实完全如 P0.3 所说，P0.3 = T 的概率也只有 P(Bin(9, 0.6) ≥ 6) × P(Bin(9, 0.75) ≥ 6) ≈ 0.48 × 0.83 ≈ 0.40。清单第 8 条要求的"按已知错误率写容差"在这里没有做到。
- 另外，在 κ ≳ 9.5 时，θ gate（n = 8000）对撕开图读 0.989–0.990（4 个状态样本，恰好落在阈值两侧），对粘合图读 0.9925，对撕开不利，而这些 run 又会以"不承载 θ"的身份留在分母里。
- 改法（需要 Z）：
  - 率只在有结论的 run 上算（glued / torn / not_carrying_theta）；有结论的 run 少于 6 个就记 I。
  - θ gate 不过且 κ̂ > 5 的 run 记为 inconclusive：这已超出 gate 的校准范围。
  - T / F 的判法对称：例如 P0.3 = F 要求反面结果确实出现（recon-mse 粘合率 ≥ 1/3，或 recon-circular 撕开率 ≥ 1/3，等等，事先写死）；其余情况为 I。
  - 机制 notes 按撕开率写（"撕开"指撕开率 ≥ 2/3），不按"不是 T"写。
  - 用校准的判定率算出各预测在真为 T 时的通过概率，写进 §6。

**B2. 仪器检查没成立也能出判定。**
- 代码：`stop` 只认 "fail"（`:106`）。
- 伪造测量的结果：负对照整组缺失时，P0.2 = missing → DECIDED；cs-recon 全部没过逐点检查时，P0.1 = insufficient → DECIDED；4 个 unstable + 5 个 none 时，P0.1 = insufficient → DECIDED。
- 改法：阶段 1 的 DECIDED 要求 angle_cs 的 P0.1 与 P0.2 都是 pass。insufficient 或 missing 记为 "INSUFFICIENT"，不更新任何邻居。像素在阶段 1 缺失时，判定标为"暂定"。写明阶段 2 的像素 STOP 是否撤回阶段 1 的改动。

**B3. 塌缩判据的"有效秩"换了定义（违反清单第 4 条"只因塌缩而排除"）。**
- `c0_score.py:136-142` 用协方差特征值的熵。v1 的 gate 和 `results/bench_cpu.md` 指的是 baseline `metrics.json` 里的 `effective_rank`，即 RankMe，用奇异值（`baselines/mlp_wm.py:372`）。

- 各向异性又与结局相关：高 κ 的 run 本来就是一致性表判不出的那一类。所以这里的排除会改变分母和可评判性，而且与结局相关。

**B5. P0.5 的计数与合成（阶段 2 计分前必须改，不挡阶段 1 训练）。**
